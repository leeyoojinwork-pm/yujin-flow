# Single → Multi Agent 강사 시연 런북

## 시연 목표

수강생에게 클릭 순서를 설명하지 않는다. 강사는 세 번의 시연으로 다음 흐름만 보여준다.

1. 내가 하던 일을 AI가 이해할 수 있도록 정리한다.
2. AI 한 명이 초안 파일을 만든다.
3. AI 한 명을 더 열어 초안을 확인하게 한다.

최종 화면에는 `draft.md`와 `review.md`가 함께 있어야 한다.

## 시연 전 준비

- 실제 업무 예시 1개: 회의록 정리
- 입력 파일: `input/meeting.md`
- 공통 규칙: 결과에 없는 내용은 추측하지 않고 `확인 필요`라고 적기
- 작성 AI가 만들 파일: `output/draft.md`
- 확인 AI가 만들 파일: `output/review.md`
- 시연 중 개인정보·외부 발송·파일 삭제는 사용하지 않기

## 시연 1. 내 일을 AI가 이해할 수 있게 정리하기

강사 멘트:

> “제가 매주 하던 일을 AI가 따라 할 수 있도록, 먼저 일의 순서를 파일로 정리하겠습니다.”

보여줄 것:

- 회의록 원문
- 내가 중요하게 보는 항목: 결정사항, 담당자, 기한
- 결과 파일의 모양: 제목 / 결정사항 / 다음 할 일

시연용 요청문:

```text
이 회의록을 읽고 다음 세 가지를 정리해줘.
1. 결정된 내용
2. 담당자
3. 기한

회의록에 없는 내용은 만들지 말고 “확인 필요”라고 적어줘.
결과는 제목 / 결정사항 / 다음 할 일 순서로 작성해줘.
```

완료 확인:

- 회의록에 없는 내용이 들어가지 않았는가?
- 결정사항·담당자·기한이 구분되어 있는가?

## 시연 2. AI 한 명이 초안 파일 만들기

강사 멘트:

> “이제 작성하는 AI에게 실제 자료를 맡기고, 결과를 파일로 받겠습니다.”

시연용 요청문:

```text
input/meeting.md를 읽고 회의록 정리 업무를 해줘.
결과는 output/draft.md로 저장해줘.

순서:
1. 결정된 내용 찾기
2. 담당자 찾기
3. 기한 찾기
4. 제목 / 결정사항 / 다음 할 일 형식으로 정리하기

모르는 내용은 추측하지 말고 “확인 필요”라고 적어줘.
```

완료 확인:

- `output/draft.md`가 실제로 생겼는가?
- 작성 AI가 자료를 읽고 정리했는가?
- 사람이 마지막에 확인할 부분이 남아 있는가?

## 시연 3. AI 한 명을 더 열어 결과 확인하기

강사 멘트:

> “두 번째 AI는 새로 작성하지 않습니다. 첫 번째 AI가 놓친 부분만 찾습니다.”

시연용 요청문:

```text
너는 회의록 결과 확인 담당이야.

1. input/meeting.md와 output/draft.md를 읽어.
2. draft.md에 회의록 원문에 없는 내용이 들어갔는지 확인해.
3. 결정사항·담당자·기한 중 빠진 항목이 있는지 확인해.
4. 문제가 있는 부분만 output/review.md에 적어.

표 형식:
어디가 | 무엇이 문제인가 | 원문 근거

draft.md는 고치지 마.
```

완료 확인:

- `draft.md`와 `review.md`가 모두 있는가?
- 두 번째 AI가 초안을 직접 고치지 않았는가?
- 최종 수정 여부는 사람이 판단하게 남겨두었는가?

## 시연 중 강조할 한 문장

> “Multi Agent는 AI를 많이 쓰는 방법이 아니라, 작성하는 일과 확인하는 일을 나누는 방법입니다.”

## 수강생 질문이 나오면

- “몇 개까지 나누나요?” → 처음에는 작성 1개와 확인 1개로 시작합니다.
- “AI가 알아서 고치면 안 되나요?” → 오늘은 확인 결과를 사람이 보고 고치는 구조로 둡니다.
- “모든 업무를 나눠야 하나요?” → 중간에 넘길 파일이 있을 때만 나눕니다.
