PROBLEM DEFINITION09

“피드백 PDF를 만들어줘”를
업무 문제로 다시 씁니다.

멘토가 매주 멘티 과제를 읽고 핵심 진단, PDF 문장, 전달 멘트를 각각 새로 정리하느라 피드백의 일관성과 다음 행동 설계에 시간을 충분히 쓰기 어렵다.
좋은 출발점
최종 산출물은 PDF와 멘트지만, 해결해야 할 문제는 진단을 일관된 산출물로 번역하는 반복 업무입니다.

MENTORING OS / MULTI AGENT11

멘토링 OS를
멀티 Agent 구조로 나눕니다.

HEAD AGENT

멘토링 OS 오케스트레이터

제출물을 확인하고 네 Agent에 작업을 나눈 뒤, 결과를 모아 멘토의 최종 판단을 기다립니다.

SUB AGENT 01

진단 Agent

제출물에서 핵심 신호를 뽑습니다.

  • 제출물 분석
  • 유형 분류
  • 우선 보완점
SUB AGENT 02

PDF Agent

정해진 구조로 피드백 리포트를 만듭니다.

  • 리포트 구성
  • 문장 정리
  • PDF 생성
SUB AGENT 03

멘트 Agent

멘티가 바로 움직일 전달 멘트를 만듭니다.

  • 멘토 톤 적용
  • 핵심 요약
  • Next Step
SUB AGENT 04

검수 Agent

PDF와 멘트가 같은 진단인지 확인합니다.

  • 진단 일치
  • 행동 가능성
  • 발송 안전성
검수 결과가 Head Agent로 돌아감불일치하면 관련 Agent에 다시 보내 수정하고, 통과하면 멘토 승인 단계로 이동합니다.
멘토 검수 게이트 최종 진단, 표현의 강도, 외부 발송 여부는 사람이 결정합니다.
QUALITY LOOP12

PDF와 멘트가
같은 진단을 말하는가?

통과 기준을 먼저 씁니다.

좋은 피드백이라는 말 대신, PDF와 멘트가 어떤 상태면 통과인지 미리 정합니다.

CHECK 01

진단 일치

PDF와 멘트가 같은 핵심 문제를 말하는가?

CHECK 02

행동 가능성

멘티가 다음에 무엇을 할지 바로 알 수 있는가?

CHECK 03

톤 구분

PDF는 분석체, 멘트는 자연스러운 대화체인가?

CHECK 04

발송 안전성

과장, 단정, 개인정보 노출 없이 발송 가능한가?

Evaluator가 불일치 사유를 남기고, Optimizer가 PDF와 멘트를 함께 수정합니다.
